THE TOX TECHNIQUE — INFLUENCER OUTREACH & DATABASE PLATFORM
MASTER BUILD SPECIFICATION FOR ANTIGRAVITY

ROLE
You are the lead product engineer, UI/UX designer, database architect, and QA engineer. Build a production-quality internal web application for The Tox Technique, a marketing agency whose staff perform influencer outreach from multiple Instagram accounts.

This is an internal operational system, not a generic CRM template. Do not build a pretty dashboard around a weak data model. The application must make it easy to submit outreach, search the influencer database, detect repeat outreach, manage accounts/staff, and eventually scale to thousands or tens of thousands of records.

CORE BUSINESS MODEL

There are approximately:
- 15 employees/staff members
- ~70 Instagram marketing accounts
- Each employee has access to approximately 10 accounts
- Multiple employees can have access to the same account
- Employees submit approximately 30–40 influencer handles per day

- The same influencer can legitimately appear under multiple geographically related accounts
- Example: Dallas-area accounts such as Southlake, McKinney, etc. may target the same influencer

CRITICAL DATA PRINCIPLE

Do NOT treat "influencer" and "outreach" as the same thing.

An influencer is a unique person/account in the master database.

An outreach is an event/record connecting:
Employee → Marketing Account → Influencer → Date/Time → status/metadata.

Example:

Influencer:
@jessicajane

Outreach #1:
Daniyal → Alamo → @jessicajane → Sept 1

Outreach #2:
Ahmed → McKinney → @jessicajane → Sept 3

Outreach #3:
Daniyal → Alamo → @jessicajane → Oct 8 → REPEAT

The influencer remains ONE database record.

The three outreach records remain THREE historical records.

DUPLICATE/REPEAT LOGIC

This distinction is essential.

Case A:
@jessica contacted from Alamo.
Later @jessica contacted from McKinney.

Result:
- Same influencer
- Different account
- Legitimate outreach
- Do NOT classify as a same-account repeat
- Show the cross-account history

Case B:
@jessica contacted from Alamo.
Later @jessica contacted from Alamo again.

Result:
- Same influencer
- Same account
- Create a new outreach record
- Flag it as REPEAT
- Preserve both records
- Show the dates when dates exist
- Show repeat count

Do not silently block repeat outreach. Flag it.

The system should eventually be able to display:

@jessica
Total outreach: 4
Accounts contacted: 3
Alamo: 2 outreaches — 1 repeat
McKinney: 1
Southlake: 1
Last outreach: [date]
First outreach: [date]

If no historical date exists, show "Historical / date unavailable" rather than inventing a date.

HANDLE NORMALIZATION

Normalize Instagram handles before matching.

These should resolve to the same canonical handle:
@JaneSmith
janesmith
JANEsmith
https://instagram.com/janesmith
https://www.instagram.com/janesmith/

Store a canonical normalized form such as:
janesmith

Display the user's preferred formatting such as:
@janesmith

Strip whitespace, @, URLs, query parameters, trailing slashes, etc.

Exact normalized handle matching should be the first duplicate detection mechanism.

Do not merge people based solely on display name.

REPEAT CALCULATION

When a new outreach is submitted:

1. Normalize handle.
2. Find/create influencer.
3. Identify account.
4. Look for prior outreach records for the same influencer + same account.
5. If none:
   is_repeat_same_account = false
   repeat_count_for_account = 0
6. If one or more:
   is_repeat_same_account = true
   repeat_count_for_account = number of previous same-account outreach records
   previous_outreach_id = most recent prior same-account outreach
7. Never delete or overwrite the previous outreach.

Cross-account previous outreach should be visible but should not trigger the same-account repeat flag.

IMPORTANT PRODUCT PHILOSOPHY

The most important thing is the data model.

The UI can be changed later.
The database should not need to be rebuilt because the initial implementation confused influencers with outreach.

One influencer = one canonical influencer record.

Every outreach = a separate historical event.

Same influencer across different accounts = legitimate cross-account activity.

Same influencer + same account = repeat outreach and must be flagged.

The application should make that distinction obvious to both humans and the underlying database.

Use the supplied "influencer track - Sheet1.tsv" as a real-world messy-data reference while building the migration/import workflow.
